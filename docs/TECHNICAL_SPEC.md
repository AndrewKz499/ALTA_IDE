# AltaIDE — Technical Specification

## 1. Назначение

Документ фиксирует общие технические требования к кодовой дизайн-системе и интерактивным прототипам AltaIDE. Он предназначен для переноса проекта в другой репозиторий или среду без потери архитектурных правил.

## 2. Технологии

Базовый стек:

- HTML5;
- CSS3;
- Vanilla JavaScript;
- статические ресурсы;
- без обязательного build step;
- без npm-пакетов и UI-фреймворков по умолчанию.

Историческое ТЗ для статического экрана задаёт совместимость как минимум с Chrome 90+, Edge 90+, Firefox 88+ и запуск через `file://`.

## 3. Требования к запуску

Каждый component preview и каждый prototype должен:

- открываться прямым запуском HTML-файла;
- использовать только относительные пути;
- не зависеть от локального HTTP-сервера;
- не использовать `fetch()` для подгрузки локальных HTML-фрагментов;
- работать на GitHub Pages без изменения путей.

## 4. Структура слоёв

```text
Figma variables
    ↓
tokens/source/*.tokens.json
    ↓
tokens/tokens.css
    ↓
components/*
    ↓
prototypes/*
```

Нижний слой не должен зависеть от верхнего: токены не знают о компонентах, компоненты не должны зависеть от конкретного prototype layout.

## 5. Токены

- `tokens/source/*.tokens.json` — source of truth.
- `tokens/tokens.css` — generated artifact; ручное редактирование запрещено.
- Компоненты используют semantic tokens.
- Прямое использование primitive tokens в компонентах не допускается, кроме документированного исключения.
- Хардкод HEX/RGB/размеров при наличии токена запрещён.

## 6. Компоненты

Канонический путь: `components/<component-name>/`.

Структура:

```text
index.html
<component-name>.css
<component-name>.js   # только если поведение необходимо
preview.html
README.md
```

Нельзя создавать группирующие каталоги типа `actions/button/`.

## 7. Темизация

Поддерживаются Light и Dark через semantic CSS variables.

```html
<html data-theme="light">
<html data-theme="dark">
```

Тема не должна менять DOM, размеры или поведение компонента.

## 8. Prototype layer

`prototypes/` содержит layout экранов и сценариев.

Разрешено в screen CSS: grid/flex layout, размеры областей, позиционирование зон, композиция компонентов.

Запрещено: копировать CSS компонента внутрь prototype, переопределять внешний вид reusable component, создавать временный локальный компонент вместо добавления его в `components/`.

Если нужного компонента нет, сначала создаётся gap в `docs/gap/`, затем компонент.

## 9. Assets

- Иконки и изображения хранятся в `assets/` или локальном `assets/` компонента, если ресурс строго компонентный.
- Используются оригинальные Figma assets/vector paths, если они доступны.
- Не допускаются визуальные приблизительные замены при наличии исходного ассета.

## 10. Типографика

Основной UI-шрифт — Rubik. Для code/editor content используется JetBrains Mono там, где это задано Design System. Line-height задаётся явно.

## 11. JavaScript

JavaScript добавляется только для реального поведения. Нативное HTML-поведение не дублируется без необходимости. Код должен корректно работать при нескольких экземплярах компонента на одной странице.

## 12. Совместимость и доступность

Обязательны keyboard navigation, `:focus-visible`, semantic HTML, `aria-*` там, где семантики HTML недостаточно, корректные disabled/loading states и отсутствие console errors.

## 13. Версионирование

- Conventional Commits.
- Компонент получает версию в `docs/component-registry.md`.
- Прототип фиксируется commit/tag в `docs/prototypes-registry.md`.

## 14. Definition of Done

Изменение готово, если реализованы заявленные variants/states, Light/Dark проверены, Preview работает, README и registry обновлены, относительные пути работают через `file://`, отсутствует дублирование component CSS в prototypes и нет ошибок в консоли.
