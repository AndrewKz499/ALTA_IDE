# AltaIDE — Project Overview

## Назначение

AltaIDE в этом репозитории — дизайн-система и набор интерактивных браузерных прототипов для интерфейса IDE. Процесс строится по цепочке:

`Figma → variables/tokens → GitHub → components → prototypes/screens → scenarios`

Цель — переносить дизайн из Figma в переиспользуемые кодовые компоненты, собирать из них экраны и проверять продуктовые гипотезы на живых прототипах без отдельной продуктовой сборки.

## Основной цикл

1. Дизайнер формулирует гипотезу.
2. Нужные компоненты проверяются в Design System и `docs/component-registry.md`.
3. Если компонента нет, он сначала реализуется в `components/`.
4. Экран собирается в `prototypes/` только из готовых компонентов.
5. Прототип публикуется через GitHub Pages.
6. После исследования изменения возвращаются на уровень токенов/компонентов/экрана в зависимости от причины проблемы.

Ядро продуктового процесса: **гипотеза → прототип → тест → правка**.

## Основные пользовательские сценарии

- Быстрая проверка продуктовой гипотезы.
- Быстрая итерация после пользовательского теста.
- Исследование на интерактивном прототипе с настоящими состояниями и вводом.
- Самодокументирование компонентов через README и Preview.
- Воспроизводимость исследований по commit/tag.
- Переиспользование ранее проверенных сценариев.
- Передача подтверждённого решения в разработку через соответствие Figma variants ↔ code states/props.

## Источники истины

- **Figma `🧩 AltaIDE DS`** — визуальная спецификация, variables, components, variants.
- **`tokens/source/*.tokens.json`** — источник истины для дизайн-токенов.
- **`tokens/tokens.css`** — сгенерированный CSS-слой токенов; вручную не редактируется.
- **`components/`** — кодовая реализация дизайн-системы.
- **`docs/component-registry.md`** — состояние компонентов.
- **`prototypes/`** — экраны и сценарии.
- **`docs/prototypes-registry.md`** — версии и статусы прототипов.

## Технологический профиль

Проект ориентирован на статическую реализацию:

- HTML5;
- CSS3;
- Vanilla JavaScript;
- без npm-пакетов и UI-фреймворков, если иное не оговорено отдельно;
- относительные URL;
- запуск через `file://`;
- публикация через GitHub Pages.

## Правило переноса в другой проект

Перенос считается корректным только если сохраняются:

1. семантическая модель токенов;
2. единый DOM для Light/Dark;
3. прямое соответствие Figma Component → `components/<name>/`;
4. README + Preview для каждого компонента;
5. сборка экранов только из готовых компонентов;
6. registry для компонентов и прототипов;
7. воспроизводимость через Git commit/tag.

См. также: `ARCHITECTURE.md`, `DESIGN_SYSTEM_SPEC.md`, `COMPONENT_SPEC.md`, `INTERACTION_SPEC.md`, `MIGRATION_GUIDE.md`, `TECHNICAL_SPEC.md`.
